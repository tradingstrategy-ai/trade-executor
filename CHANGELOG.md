- Fix `analyse_grid_search_result()` and `analyse_optimiser_result()` raising `KeyError('Expected Shortfall (cVaR)')` on any result set containing a crashed backtest. QuantStats emits a reduced metric set for a degenerate returns series, and `calculate_advanced_metrics()` downgrades to `basic` mode when the series is empty or constant - which is what `create_grid_search_failed_result()` produces for a crash, and what a backtest that never opened a position produces on its own. That drops 29 of the 65 metrics, including the only `METRIC_REGISTRY` entry not present in both modes. The table builder assumed every registered metric was always available, so one crashed combination out of hundreds took down the whole table, hiding every healthy row with it. Two other readers walked a whole result set through the same strict accessor: `optimise_cvar()`, where a single crashed backtest aborted the entire optimisation because crashes reach the search function before any `result_filter` runs, and `order_grid_search_results_by_metric()`. Reading a metric that may legitimately be absent is now the separate `GridSearchResult.get_metric_or_nan()`, so the table blanks the cell, the objective skips the result and the sorter ranks it last, while `get_metric()` still asserts for a caller that named one metric. Table tolerance is bounded by `OPTIONAL_METRICS` - a result missing a metric that both modes emit is corrupt and still raises rather than being quietly blanked (2026-08-11)

- Fix Hypercore vault position profit attribution double-counting. `get_unrealised_profit_usd()` returned the internal share-price model's whole-position profit regardless of whether anything was still held, so a closed position reported its entire P&L as unrealised and any caller summing realised + unrealised counted it twice. For open positions realised came from lifetime average cost while unrealised came from the share-price model, which measures profit on the currently outstanding internal supply - two bases that stop complementing each other once a position is partially sold and rebought at another price, with the error growing on every trade. A position traded 59 times reported 13,028 USD of profit against 6,185 USD implied by its own cash flows, which made position-level P&L unusable for the heavily traded positions a rebalancing strategy produces. These positions now anchor to cash-flow profit - proceeds, plus holdings, minus cost - so the two halves sum to the truth by construction. Exchange account positions share the code path but keep the share-price model, because they establish capital through a valuation sync rather than a trade. Equity and NAV were never affected (2026-08-10)

- Fix indicator lookups inheriting the candle width of an unrelated time series, which could substitute the current bar's indicator value for the previous one. `_calculate_and_cache_candle_width()` keyed its cache on `id(index)`, but `id()` is unique only among live objects: indicator lookups build short-lived series, so a collected index frees its address for the next one and the cache serves the dead index's width.
