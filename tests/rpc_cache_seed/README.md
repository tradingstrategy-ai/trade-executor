# Project Foundry RPC cache seeds

This tree mirrors Foundry's `rpc/<network>/<block>/storage.json` layout. Test
startup copies these entries into the live Foundry cache after eth-defi's
default seeds, without replacing an existing cache file.

The entries are generated by their focused fixed-block test modules:

- `arbitrum/484000000`: `tests/exchange_account/test_gmx_valuation_integration.py`
- `arbitrum/470000000`: `tests/erc_4626/test_vault_async_cli_commands.py`
- `base/27975506`: IPOR pricing, status, deposit/redeem and trading tests in
  `tests/erc_4626/`
- `base/35094246`: `tests/erc_4626/test_vault_pricing_erc_7540.py`
- `base/41950000`: `tests/erc_4626/test_vault_async_lagoon_erc_7540.py`
- `base/45960642`: cross-chain Base fixtures in `tests/mainnet_fork/`
- `mainnet/20000000`: `tests/mainnet_fork/aave_v3/test_aave_v3_live_credit_supply.py`
- `polygon/51000000`: `tests/ethereum/polygon_forked/generic-router/`

Historical repair tests use a distinct original chain state for every incident.
The committed repair cache blocks are listed in `tests/mainnet_fork/README.md`.
The legacy signing-key repair at Polygon block `49132512` is normally skipped,
so it is intentionally not seeded until that credential is available.

Regenerate an entry by setting `FOUNDRY_RPC_CACHE_DIR` to an empty external
directory, running the focused test module, and copying its generated
`storage.json` here after Anvil exits cleanly.

The seed serves repeatable historical reads after Anvil has started. Its initial
chain-identity and archive preflight are remote by design and, when configured
with multiple providers, must use their bounded failover proxy rather than one
selected endpoint.
